# Buildathon Track

## Selected Track
**AI Revenue Recovery**

## Why It Fits
The project directly addresses revenue slipping away after payment failure. It:
1. detects revenue at risk,
2. diagnoses context,
3. selects an intervention,
4. executes a bounded action,
5. measures recovered money,
6. compares against a baseline,
7. records audit/guardrail outcomes.

## Judging Emphasis
Emphasize:
- incremental recovered revenue,
- contextual decisioning,
- bounded execution,
- guardrails,
- audit trail,
- held-out evaluation,
- real Razorpay Test Mode execution,
- graceful failure handling.

## Avoid
Do not pitch RecoverAI as:
- a new retry engine,
- a generic AI assistant,
- a replacement for Razorpay recovery,
- a guaranteed revenue-uplift product.

## Demo Proof
The ideal proof combines large-scale synthetic evaluation with one or more genuine Razorpay Test Mode executions.
